# Contributing

Thanks for taking the time to contribute. This project welcomes bug reports,
feature suggestions, documentation fixes, and code contributions that fit the
project's scope. If you are unsure whether something is in scope, open an issue
and ask before investing significant effort.

## Reporting Bugs

1. Check the existing issues first — the bug may already be reported or fixed.
2. If you cannot find it, open a new issue and describe the problem clearly.
3. Include what you expected to happen, what actually happened, and the steps to
   reproduce it.
4. Include your environment details (operating system, runtime or tool version,
   and package version) and any relevant error output.

Do not include secrets, credentials, or other sensitive data in an issue.

## Suggesting Features

Open an issue describing the problem you want solved and why it matters.
Explain the use case rather than only the proposed implementation, so it can be
evaluated against the project's scope. Large or architectural changes should be
discussed in an issue before any code is written.

## Pull Request Workflow

1. Fork the repository.
2. Create a branch for your change.
3. Make your change, including tests or documentation updates where relevant.
4. Commit your work following [docs/GIT_GUIDELINES.md](docs/GIT_GUIDELINES.md)
   for commit expectations and Git practices.
5. Open a pull request against the default branch. Describe what the change
   does, why it is needed, and how you verified it.

Keep pull requests focused on a single concern. Small, reviewable changes are
merged fastest. If a change is not ready for review, open it as a draft.

## Coding and Design Standards

Follow [docs/DESIGN_GUIDELINES.md](docs/DESIGN_GUIDELINES.md) for coding and
design standards. These are baseline principles; project-specific requirements
take precedence where they exist.
